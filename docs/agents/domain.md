# Domain Docs

本儲存庫採單一上下文（single-context）。
本文件定義工程技能探索程式碼時，如何讀取及使用領域文件。

## 探索前先讀取

- 根目錄的 `CONTEXT.md`：領域概念、術語與詞彙定義。
- 根目錄的 `docs/adr/`：閱讀與目前工作範圍相關的架構決策紀錄。

若上述文件不存在，靜默繼續工作，不必提醒缺少文件，
也不要僅因文件不存在而建議預先建立。

領域術語或決策實際確立時，再由 `/domain-modeling` 逐步建立文件；
該技能也可能由 `/grill-with-docs` 或
`/improve-codebase-architecture` 引導使用。

## 文件位置

- 領域上下文：`CONTEXT.md`
- 架構決策紀錄：`docs/adr/`
- ADR 檔名：使用流水號與描述，例如 `0001-<decision-name>.md`。

## 使用領域詞彙

在議題標題、重構提案、診斷假設或測試名稱中提及領域概念時，
使用 `CONTEXT.md` 定義的術語，避免改用詞彙表明確排除的同義詞。

若需要的概念尚未列入詞彙表，先確認它是否符合專案既有用語。
若確實存在詞彙缺口，記錄下來供 `/domain-modeling` 處理。

## 明確指出 ADR 衝突

若提案或輸出與既有 ADR 衝突，明確指出相關 ADR 與重新評估的理由，
不要默默覆蓋既有決策。
